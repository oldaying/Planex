## Context

The v0.5→v0.6 audits surfaced a clean pattern. Axioms with a mechanism carrier score strong: state–presentation separation is enforced by pure-function Perception, and metaphor replaceability is enforced by multi-Perception. Axioms that live only in documentation drift: the semantic-primitive axiom leaks through `void*` payloads, the feedback axiom shipped without a time budget until v0.6, and the channel axiom still terminates at stderr.

**v0.7 is the version where the remaining doc-only axioms get their judges.** Each main line pairs a drift surface with the mechanism that makes drift impossible — or at least loud:

| Main line | What it judges | Mechanism |
|---|---|---|
| 1. Intent compilation (afford/region) | interaction routing on raw coordinates | typed hit-target registry + AFFORDS graph query, promoted from prototype |
| 2. Budget as contract | feedback without time constraints | default frame budget + enforced propagation accounting |
| 3. Estimate schema | `void*` payloads without a semantic contract | opt-in typed-value descriptor |
| 4. a11y platform bridge | the accessibility channel ending at stderr | AT-SPI2 adapter behind the v0.6 query-side contract |
| 5. Closure constructor split | the last L2 leak (`bind_graph` ordering) | constructor shape that makes the dependency impossible to forget |

Two cross-cutting decisions (interaction promotion, Path C adoption posture) and one new practice (the conditions ledger) complete the plan.

### New practice: the conditions ledger

The 60-year Path C failure record ([path-C-lineage.md](../background/path-C-lineage.md)) reads, on audit, as a record of **condition misjudgments rather than idea errors**: Lisp-machine presentation types lost an economic war, not an argument; constraint toolkits lost a decade to missing incremental-solve theory; single-board hypertext lost to the absence of distribution infrastructure. The ideas were sound; the conditions were not there.

The practice that follows: every capability documents the external conditions it depends on, its current readiness against those conditions, and who owes the next proof. A capability whose conditions are not ready is **seeded, not built** (the v0.6 Friston seeds are the precedent); a capability whose conditions are ready but unclaimed is a **priority** (see Line 1). The ledger below is the v0.7 planning snapshot; when v0.7 ships, each row migrates into its abstraction's canonical doc.

| Capability | External conditions | Readiness (at v0.6) | Proof obligation |
|---|---|---|---|
| Estimate | none — host-portable | **ready and contracted (v0.7, Line 3)** — schema landed; the void* contract half retired | pointer half = permanent host cost (documented) |
| Closure | none — host-portable | **ready and clean (v0.7, Line 5)** — aggregate L2 = 0% | hold at zero: the budget gate catches any new L2 |
| Relation | none — host-portable | ready | — |
| Perception | backend surface (headless / x11 / win32 / cocoa) | ready — headless is first-class | — |
| px_loop | measurable frame timing | **ready and contracted (v0.7, Line 2)** — default 16ms budget + propagation accounting + overrun loudness | propagation-depth semantics for replay paths |
| `px_interaction` | input-event richness of the event layer | **ready and promoted (v0.7, ADR-0018)** — real-application evidence delivered (`palette_afford.c`); touch events remain NG-6 | multi-process arbitration when touch lands |
| intent compilation | an integration point in app-level event routing | **ready and promoted (v0.7, ADR-0017)** — `intent_graph` routing in `app.c`, real app with zero raw-coordinate callbacks | keyboard affordances + drag-begin seam (limitations L15) |
| a11y query side | none — the contract is local | ready — API landed in v0.6 | — |
| a11y bridges | platform accessibility APIs (AT-SPI2 / UIA / NSAccessibility) | **partial — AT-SPI2 adapter landed (v0.7, Line 4, behind the flag); CI compile-probe wired** | orca end-to-end pass on x11; UIA/NSAccessibility adapters follow the same shape |

The ledger is **state, not aspiration**: a row flips only in the PR that moves the capability.

## Line 1: Intent compilation — afford/region promotion (highest priority)

### Problem

`px_region` + `px_afford_at` are prototype-only (v0.6). The AFFORDS graph query exists, but nothing in real event routing depends on it — an application still writes `on_click(ev.x, ev.y)` and does its own hit-testing. The prototype therefore proves the query works without proving anything routes through it.

This is also the industry-wide gap the prototype is positioned against: mainstream frameworks still route interaction on pixels and callbacks. The strongest prior claim on the alternative — presentation-typed interaction routing (CLIM, 1980s) — died with its host for economic reasons, not because the idea was refuted. The conditions that killed it (an expensive closed ecosystem) no longer hold; the claim is unclaimed. Planex's version of the claim has a specific advantage over the nearest mainstream successor: the type drives **interaction routing itself**, not just read-only navigation (LSP-style "click to definition" is the weakest projection of this idea).

### Goal

Promote intent compilation from prototype to the canonical 6th capability — or retire it with documented evidence. Both outcomes are acceptable; the admission bar ([ADR-0011](../../decisions/accepted/ADR-0011-essence-justified-abstraction-exempts-rule-of-three.md)) decides, not enthusiasm.

### Tasks

1. Add an opt-in routing path in `app.c`: resolve `px_afford_at` against the region registry before dispatching pointer events; raw-coordinate dispatch remains the fallback.
2. Write one real application (see Cross-cutting A) whose click handling has **zero raw-coordinate callbacks**.
3. Re-score Category D of the [ui-pattern-corpus](../../reference/ui-pattern-corpus.md) against the afford path.
4. Promotion ADR passing the ADR-0011 admission bar: tradition citation, orthogonality test, denotational semantics, negative consequences.
5. On promotion: update `limitations.md` (L12/L14), `roadmap-matrix.md`, leak-budget entries for the new API surface, and the abstraction-count references across v0.5-current docs (the `check_stale_abstraction_count` gate then enforces the new count).

### Success criteria

- A real application routes all pointer interaction through the AFFORDS query.
- Category D re-scored with the afford path; corpus gate (`make check-completeness`) green.
- Promotion ADR accepted, or prototype retired with the evidence recorded.

**Estimated effort**: 3–4 weeks.

## Line 2: Budget as contract

### Problem

v0.6 landed `px_loop_set_budget` and per-iteration audit fields (`iteration_ms` / `budget_ms` / `budget_exceeded`) — but the budget is opt-in, unenforced, and only recorded. The propagation cost through Relation graphs is not accounted at all: an audit entry answers "what did the frame cost" but not "what did propagation cost".

The constraint-toolkit lineage is the caution here: Garnet/Amulet's one-way dataflow constraints were the right idea and still lost a decade to performance and robustness gaps that were never made measurable. A budget that is never set by default repeats that failure mode in miniature.

### Goal

Make the feedback axiom's time budget contractual: every loop has a budget, every overrun is loud, propagation cost is measurable.

### Tasks

1. Default budget on `px_loop_init` — finite and documented; zero remains available as an explicit opt-out, not a silent default.
2. Propagation accounting: Relation-graph traversal cost (depth, nodes visited) into the audit entry.
3. Overrun behavior: assert in debug builds, warn once in release builds.
4. Regression test locking the contract: a loop that overruns must fail loudly in debug; a loop without a budget must be an explicit opt-out.

### Success criteria

- No `px_loop` ships without a budget unless it explicitly opted out.
- The audit entry answers both cost questions (frame and propagation).
- Silent degradation is impossible by construction.

**Estimated effort**: 1–2 weeks.

## Line 3: Estimate schema

### Problem

The last remaining L1 leak: `void*` payloads on Estimate values, currently documented as "intrinsic to C". That verdict is true for the pointer but not for the contract. Rich-typed hosts give every value a type for free; a C framework can pay for the same semantics explicitly. Without a describable contract, tests cannot assert on value kind, a11y cannot name values, and the semantic-primitive axiom stays documentation-only — the exact drift pattern the Context section describes.

### Goal

An opt-in typed-value descriptor beside the payload: kind tag, size, optional operations (print / equal / clone). Not a type system — a **describable contract**.

### Tasks

1. `px_estimate_schema` struct + `px_estimate_set_schema` (opt-in; zero cost when unset — the zero-dependency rule is non-negotiable).
2. Kind-aware test assertions: "this estimate is INT and equals 3", not byte equality on a pointer.
3. The a11y query side reads the schema for value naming (feeds Line 4).
4. Leak-budget update: the `void*` L1 entry gains its retirement path — the contract half closes, the pointer half is documented as permanent host cost.

### Success criteria

- At least one example carries schema-typed estimates asserted kind-wise in tests.
- The semantic-primitive deviation shrinks from "undocumented `void*`" to "documented host cost with an available semantic contract".

**Estimated effort**: 1–2 weeks.

## Line 4: a11y platform bridge (AT-SPI2 first)

### Problem

L9: accessibility is logging-only. The v0.6 query-side API (getters, announcement ring, `set_verbose`) was designed precisely so that the bridge would be a **replaceable adapter**, not an ontology commitment — the Lisp-machine lesson applied: never bet the abstractions on a host condition that can die.

### Goal

Linux first: an AT-SPI2 adapter that maps the v0.6 query-side contract onto the platform. The adapter is a backend in the same sense as x11/win32/cocoa; no abstraction file changes to achieve it.

### Tasks

1. `src/a11y_bridge_atspi.c` behind the existing `a11y.h` contract (build flag `PX_A11Y_ATSPI`).
2. Map roles, states, and announcements onto AT-SPI2 equivalents.
3. `PLATFORMS.md`: Linux flips from "logging-only" to "AT-SPI2 (query side)".
4. `limitations.md` L9 partial-resolution update in the same PR.

### Success criteria

- A Planex app is navigable by a Linux screen reader (orca) in the x11 backend.
- Zero changes to the canonical abstractions' sources.

**Estimated effort**: 2–3 weeks. External condition: AT-SPI2 development headers — the ledger row tracks this; if the condition fails on CI, the adapter ships behind the flag and the row stays "partial".

## Line 5: Closure constructor split (the last L2 retire)

### Problem

The single remaining aggregate L2 leak: `px_closure_bind_graph(c, g)` has an ordering dependency — it must be called before `trigger` if relations are needed, and the type system does not enforce this. v0.6 made the omission loud (one-time stderr warning); loud is a mitigation, not a retirement.

### Goal

Constructor shape that makes the dependency impossible to forget: a create-with-graph constructor variant, with the two-call form moved onto a deprecation path per the [deprecation registry](../../reference/deprecation-registry.md).

### Tasks

1. `px_closure_create_with_graph(closure, ops, graph)` (or equivalent) — the graph arrives with the closure, before any trigger can race it.
2. Deprecate the two-call form following the existing registry process.
3. Flip the leak-budget row: aggregate L2 1.7% → 0%.
4. Migration note in `UPGRADING.md`.

### Success criteria

- The ordering warning is gone because the ordering mistake is unwritable.
- Aggregate L2 = 0%; the leak-budget gate holds it there.

**Estimated effort**: 2–3 days. Ships early — it is the smallest line and closes a number the project has been reporting since v0.4.

## Cross-cutting A: interaction promotion decision

ADR-0016 landed `px_interaction` as a prototype with the promotion gate explicitly deferred: real-application evidence, Category D re-scoring, and its own ADR against the ADR-0011 admission bar. v0.7 produces that evidence or it does not — the decision is not pre-committed either way.

Note the asymmetry with Line 1: afford/region promotion is a main line because it requires building the routing integration; interaction promotion is a cross-cutting decision because its evidence **rides on the same real application both lines need**. One app, two promotion decisions, one admission bar.

Also note what this roadmap does **not** claim: no touch or gesture input support (NG-6 stands). The prototype makes gestures *derivable from trajectories*; a recognizer stack remains future work.

## Cross-cutting B: Path C adoption posture

[path-C-lineage.md](../background/path-C-lineage.md) records that every Path C project in 60 years died, retreated to academia, or pivoted to a hybrid. The conditions-ledger reading of that record yields two postures, both documentation-scale:

1. **Host separability is a stated property.** The canonical abstractions (7 since the v0.7 promotions) are invariants; C17 is the first host, not the ontology. `abstraction-form.md` and `intent.md` each gain a short section: the abstractions are portable, the host is replaceable, and if the embeddability bet fails the ideas move hosts rather than die with one. (This is also the honest answer to the biggest single objection to a C UI framework.)
2. **No ecosystem-rewrite demands.** The adoption wedge stays zero-dependency drop-in — the exact demand that killed Intentional Programming was requiring the ecosystem to abandon its standard interfaces. Every v0.7 line must remain embeddable without asking any toolchain to change: Line 3's schema is opt-in, Line 4's bridge hides behind a build flag, Line 2's default budget has an explicit opt-out.
