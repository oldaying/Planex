---

## Context

v0.3 proved each abstraction is **necessary** (anti-pattern tests) and **implemented** (Phase 1 + Phase 2 + undo). But it hasn't proven they work together in a **real application** — all current demos are counter/calculator complexity, not production-like.

v0.4 closes this gap.

---

## Phase 1: Real application demo (highest priority)

### Goal

Write a demo that exercises all 4 abstractions in a production-like scenario. Prove Planex can build real UI, not just toy counter apps.

### Candidate: Simple text editor

Features:
- **Closure**: edit text, save file, undo (via undo-via-graph), redo
- **Estimate**: text buffer (with derived word count), modified flag, cursor position
- **Relation**: cursor DEPENDS_ON text, word_count DEPENDS_ON text, modified DEPENDS_ON text
- **Perception**: screen render (pixels), a11y text (screen reader), file save format (serialization)

This exercises:
- Multiple Closure types (edit, save, undo, redo)
- Derived Estimates (word count, modified flag)
- Multiple Perceptions (screen + a11y + save)
- Undo in real window (Z key)
- Dynamic state (text grows/shrinks)

**Estimated effort**: 1-2 weeks.

### Success criteria

- Window opens with editable text area
- Typing updates Estimate, perception re-renders
- Word count updates in real time (derived Estimate)
- Z undoes last edit (undo-via-graph in real window)
- Save writes file (perception as serialization)

## Phase 2: HiDPI / font support

### Problem

Current bitmap font (8×16 ASCII) doesn't scale on HiDPI displays (125%/150%). Text appears too small or truncated (see v0.3 fix commit `e3a07af6`).

### Goal

Make FreeType TTF font rendering the default (not optional), with scale-aware sizing.

### Tasks

1. Make FreeType required (not optional) — remove `find_package(Freetype QUIET)`
2. Add scale parameter to font loading: `px_font_find(name, size * scale)`
3. Update all `px_fb_draw_text` calls to use TTF font
4. Test on 100%, 125%, 150% display scaling

**Estimated effort**: 1 week.

---

## Phase 3: More widget demos (new API)

### Problem

v0.3 deleted all old widget demos (slider, form, tabs, modal, todo_app) because they used the old 6-arg API. The new 4-abstraction API has only counter-style demos.

### Goal

Recreate key widgets using the new API to prove the 4 abstractions can express all common widget types.

### Widgets to recreate

| Widget | Abstractions exercised | Effort |
|---|---|---|
| `slider_4abs` | Estimate (constraints) + Relation (DEPENDS_ON) + Perception | 1 day |
| `form_4abs` | Derived Estimates (all_valid) + Closure (submit with multi-field eval) | 1 day |
| `tabs_4abs` | Relation (state-switching as graph) + Perception (tab content) | 1 day |
| `modal_4abs` | Closure (promise/declare async) + Perception (overlay render) | 1 day |
| `todo_4abs` | Dynamic derived Estimates + multiple Closures + undo | 2 days |

**Estimated effort**: 1 week total.

**Estimated effort**: 1 day (after Phase 1-3).
